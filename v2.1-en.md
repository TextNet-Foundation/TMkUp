## 1. Introduction

TMkUp (Text Markup) is a markup language for the **TNet** text network. It is designed for creating documents that:

- Are human-readable in raw form.
- Support ANSI colors and basic text formatting.
- Contain structured elements such as lists, tables, and code blocks.
- Support interactive elements, including forms and spoilers, in compatible clients.
- Allow content to be displayed in terminal environments.

**Key principles:**

- Simplicity and readability.
- Unified syntax for document elements.
- Minimalism — no conditional blocks, only static markup.
- Extensibility through versioning.
- Compatibility with terminal-based clients.

This specification defines the syntax, attributes, and display behavior of TMkUp 2.1 documents.

## 2. Document Structure

### 2.1. Metadata Block

A document may begin with an optional metadata block.

```tmkup
---tmk-meta
title: "Document Title"
author: "Author Name"
version: "2.1"
created: "2024-06-10"
variables:
  site_name: "TNet Hub"
---tmk-meta
```

Metadata may contain arbitrary keys. Clients may use them to display document information.

The `variables` key defines variables that can be referenced in the document.

### 2.2. Document Content

The document body contains markup elements described in this specification.

Elements may include:

- Headings and formatted text.
- Lists, tasks, and links.
- Images and code blocks.
- Special blocks.
- Tables and forms.
- Footnotes, comments, and variables.

### 2.3. Block Elements and Common Attributes

Block elements support a common set of block-level attributes by default.

These attributes control the appearance and behavior of block elements:

| Attribute | Description |
|---|---|
| `title` | Block heading |
| `color` | Content color and default border color |
| `border-color` | Border color |
| `border` | Border style |
| `padding` | Inner spacing |
| `align` | Content alignment |
| `title-align` | Heading alignment |
| `title-color` | Independent heading color |
| `collapsible` | Enables collapsing and expanding the block |

An individual block element may explicitly prohibit one or more common attributes when they are not applicable to that element.

Therefore, common block attributes are supported by default, but their availability is determined by the rules of each particular block type.

### 2.4. Common Attribute Behavior

Unless a specific block type defines different behavior:

- `color` changes the block content color.
- If `border-color` is not specified, `color` also determines the border color.
- If `border-color` is specified, it determines the border color independently.
- `title-color` changes the heading color independently of the content and border colors.
- `align` controls content alignment.
- `title-align` controls heading alignment.
- `padding` controls the inner spacing of the block.
- `collapsible` enables interactive collapsing and expanding.

Supported alignment values:

| Value | Description |
|---|---|
| `left` | Left alignment |
| `center` | Center alignment |
| `right` | Right alignment |

## 3. Basic Formatting

### 3.1. Headings

TMkUp supports six heading levels.

```tmkup
# Heading 1 #
## Heading 2 ##
### Heading 3 ###
#### Heading 4 ####
##### Heading 5 #####
###### Heading 6 ######
```

The number of `#` characters determines the heading level.

### 3.2. Text Styles

```tmkup
*italic*
**bold**
***bold italic***
~~strikethrough~~
==highlight==
`inline code`
^superscript^
~subscript~
```

`strikethrough`, `highlight`, `superscript`, and `subscript` are optional formatting features.

### 3.3. Horizontal Rules

Horizontal rules can be created using three or more hyphens or asterisks.

```tmkup
---
***
```

## 4. ANSI Colors

### 4.1. Foreground Colors

Colors are applied using tags in the `{color}...{/color}` format.

```tmkup
{red}Red text{/red}
{green}Green text{/green}
{blue}Blue text{/blue}
{yellow}Yellow text{/yellow}
{magenta}Magenta text{/magenta}
{cyan}Cyan text{/cyan}
{white}White text{/white}
{black}Black text{/black}
```

### 4.2. Background Colors

Background colors use the `bg-` prefix.

```tmkup
{bg-red}Red background{/bg-red}
{bg-green}Green background{/bg-green}
{bg-blue}Blue background{/bg-blue}
{bg-yellow}Yellow background{/bg-yellow}
{bg-magenta}Magenta background{/bg-magenta}
{bg-cyan}Cyan background{/bg-cyan}
{bg-white}White background{/bg-white}
{bg-black}Black background{/bg-black}
```

### 4.3. Bright Colors

Bright foreground colors use the `b` prefix.

```tmkup
{bred}Bright red{/bred}
{bgreen}Bright green{/bgreen}
{byellow}Bright yellow{/byellow}
{bblue}Bright blue{/bblue}
{bmagenta}Bright magenta{/bmagenta}
{bcyan}Bright cyan{/bcyan}
{bwhite}Bright white{/bwhite}
{bblack}Bright black{/bblack}
```

### 4.4. Bright Background Colors

Bright background colors use the `bg-b` prefix.

```tmkup
{bg-bred}Bright red background{/bg-bred}
{bg-bgreen}Bright green background{/bg-bgreen}
{bg-byellow}Bright yellow background{/bg-byellow}
{bg-bblue}Bright blue background{/bg-bblue}
{bg-bmagenta}Bright magenta background{/bg-bmagenta}
{bg-bcyan}Bright cyan background{/bg-bcyan}
{bg-bwhite}Bright white background{/bg-bwhite}
{bg-bblack}Bright black background{/bg-bblack}
```

### 4.5. Combining Colors and Styles

Color tags may contain text with other formatting.

```tmkup
{red}*Red italic*{/red}
{green}**Green bold**{/green}
{blue}***Blue bold italic***{/blue}
{red}Red {green}green inside{/green} red again{/red}
```

Color tags may be nested.

### 4.6. Resetting Styles

The `{/}` tag resets all active styles.

```tmkup
{red}Red text **{/}** and now normal
```

## 5. Lists and Tasks

Lists and tasks are separate elements. A task is a checkbox and does not require a list to be used.

### 5.1. Unordered Lists

Unordered lists use hyphens.

```tmkup
- Item 1
- Item 2
  - Nested item
    - Deep level
```

Indentation indicates nesting.

### 5.2. Ordered Lists

Ordered lists use numbered items.

```tmkup
1. First item
2. Second item
   1. Nested item
   2. Another one
```

### 5.3. Tasks

Tasks are checkbox elements that represent a completion state.

```tmkup
[ ] Uncompleted task
[x] Completed task
[~] Task in progress
```

The markers represent:

| Marker | Meaning |
|---|---|
| `[ ]` | Uncompleted |
| `[x]` | Completed |
| `[~]` | In progress |

Tasks may be used independently or as items inside a list.

Example:

```tmkup
- [ ] First task
- [x] Second task
- [~] Third task
```

### 5.4. Definition Lists

Definition lists consist of a term followed by one or more definitions.

```tmkup
Term 1
: Definition of the first term
: Second definition

Term 2
: Definition of the second term
```

## 6. Links

Links use the following syntax:

```tmkup
[Link text](/path/to/doc.tmkup)
```

The text inside square brackets is the displayed link text. The value in parentheses specifies the destination.

No tooltip support.

## 7. Images (ASCII Conversion)

### 7.1. Image Syntax

Images use Markdown-style syntax.

```tmkup
![Logo](logo.png)
![Diagram](diagram.png {height=90})
```

The text inside square brackets is the alternative text. The value in parentheses specifies the image source.

### 7.2. Image Attributes

| Attribute | Description |
|---|---|
| `height` | Desired image height in terminal characters. Optional. |

Example:

```tmkup
![Logo](logo.png {height=60})
```

### 7.3. Image Display

- The client should convert the image to ASCII art.
- The `height` parameter specifies the desired height in characters.
- Width is calculated automatically based on the image aspect ratio and the half-block rendering system.
- If image conversion is not possible, the alternative text is displayed in square brackets.

## 8. Code Blocks

### 8.1. Inline Code

Inline code uses backticks.

```tmkup
`console.log("Hello")`
```

### 8.2. Fenced Code Blocks

Code blocks use triple backticks.

````tmkup
```python
def hello():
    print("Hello World!")
```
````

An optional language identifier may follow the opening backticks.

### 8.3. Nested Code Blocks

A longer backtick fence can be used to contain a code block that itself contains triple backticks.

For example, four backticks can enclose a block containing a regular three-backtick code fence.

`````tmkup
````text
```python
def hello():
    print("Hello World!")
```
````
`````

The enclosing fence must use more backticks than the nested fence so that the nested code block does not terminate the enclosing block.

## 9. Special Blocks

TMkUp supports informational blocks, bordered blocks, spoilers, and quotes.

### 9.1. Information Blocks

Information blocks begin and end with `!!!`.

The opening marker requires a `type` attribute.

```tmkup
!!! {type="info"}
Informational message
With *formatting* support
!!!

!!! {type="warning"}
Important warning
!!!

!!! {type="success"}
Successful execution
!!!

!!! {type="error"}
Execution error
!!!
```

#### 9.1.1. Types and Display

| Type | Display color | Fixed heading |
|---|---|---|
| `info` | Blue | `INFO` |
| `warning` | Yellow | `WARNING` |
| `success` | Green | `OK` |
| `error` | Red | `ERR` |

In terminal display, the corresponding prefixes are:

| Type | Prefix |
|---|---|
| `info` | `[INFO]` |
| `warning` | `[WARN]` |
| `success` | `[ OK ]` |
| `error` | `[ERR ]` |

#### 9.1.2. Color Attributes

Information blocks support the `color` attribute.

```tmkup
!!! {type="info" color="cyan"}
Custom-colored information content
!!!
```

For information blocks:

- `color` changes the color of the block content.
- The heading and border retain their standard type-specific colors.
- `border-color` is not supported.
- `title` is not supported. The heading is determined by the block type.

### 9.2. Bordered Blocks

Bordered blocks begin and end with `%%`.

```tmkup
%%
Default bordered block
%%

%% {color="blue" border="left"}
Block with left border
%%

%% {color="green" border="rounded"}
Block with rounded border
%%
```

#### 9.2.1. Border Styles

The `border` attribute controls the block border.

| Value | Description |
|---|---|
| `rounded` | Rounded border around the block |
| `left` | Border on the left side |
| `top` | Border on the top side |
| `bottom` | Border on the bottom side |
| `vertical` | Borders on both vertical sides |
| `none` | No border |

The default border style for `%%` blocks is `rounded`.

If `border` is omitted, the client must render a rounded border.

#### 9.2.2. Block Attributes

Bordered blocks support the common block attributes defined in Section 2.3.

Example:

```tmkup
%% {title="Notice" color="cyan" border-color="blue" border="rounded"}
This block has a heading, custom text color, and a separate border color.
%%
```

#### 9.2.3. Color Behavior

- `color` sets the block content color.
- If `border-color` is not specified, `color` also determines the border color.
- If `border-color` is specified, it determines the border color independently of `color`.
- `title-color`, when specified, determines the heading color independently of the content and border colors.

Example:

```tmkup
%% {title="Status" color="green" border-color="blue" title-color="yellow"}
The content is green.
The border is blue.
The heading is yellow.
%%
```

#### 9.2.4. Padding and Alignment

`padding` controls the inner spacing between the block boundary and its content.

`align` controls the alignment of the block content.

`title-align` controls the alignment of the block heading.

Example:

```tmkup
%% {title="Centered" align="center" title-align="center" padding="2"}
Centered block content
%%
```

#### 9.2.5. Collapsible Blocks

The `collapsible` attribute allows a bordered block to be collapsed and expanded by the user.

```tmkup
%% {title="Additional information" collapsible="true"}
This content can be hidden or displayed interactively.
%%
```

When collapsing is enabled, the client provides an interaction for hiding and revealing the block content.

### 9.3. Spoilers

Spoilers begin and end with `???`.

A spoiler hides its content until the user expands it.

```tmkup
???
Hidden content
Shown on Enter press
???

??? {title="Show answer"}
Secret answer: **42**
???
```

#### 9.3.1. Spoiler Attributes

Spoilers support the common block attributes defined in Section 2.3, except where restricted by the spoiler's own behavior.

The `title` attribute specifies the displayed spoiler heading. Its default value is `SPOILER`.

Example:

```tmkup
??? {title="Secret answer"}
The answer is **42**.
???
```

In text mode, a collapsed spoiler is displayed as `[▶] Title`. If no custom title is specified, the default display is `[▶] Spoiler`.

Pressing Enter expands the spoiler.

#### 9.3.2. Color Behavior

The color behavior is the same as for bordered blocks:

- `color` changes the content color and, unless overridden, the border color.
- `border-color` changes only the border color.
- `title-color` changes the heading color independently.

### 9.4. Quotes

Standard quotes use the `>` marker.

```tmkup
> Standard quote
> Multiline quote
> — Author of the quote
```

Quotes may also include citation metadata.

```tmkup
> {cite="John Doe" date="2024"}
> Quote with author and date
```

## 10. Tables

### 10.1. Standard Tables

Tables use standard Markdown table syntax.

```tmkup
| Name | Age | City |
|------|-----|------|
| John | 25  | Moscow |
| Anna | 30  | Saint Petersburg |
| Peter| 35  | Kazan |
```

### 10.2. Column Alignment

Column alignment is specified in the separator row.

```tmkup
| Left | Center | Right |
|:-----|:------:|------:|
| text | text   | text  |
```

| Separator | Alignment |
|---|---|
| `:---` | Left |
| `:---:` | Center |
| `---:` | Right |

### 10.3. Styled Tables

TMkUp 2.1 introduces the `@@table` wrapper for applying block-level attributes to tables.

```tmkup
@@table {title="Users" color="cyan" border-color="blue" border="rounded"}
| Name | Age |
|------|-----|
| John | 25  |
| Anna | 30  |
@@
```

The wrapper applies attributes to the table as a whole.

### 10.4. Table Attributes

Styled tables support the common block attributes defined in Section 2.3.

The default table heading is empty.

### 10.5. Table Border Styles

The `border` attribute supports the following values:

| Value | Description |
|---|---|
| `rounded` | Rounded border |
| `left` | Left border |
| `top` | Top border |
| `bottom` | Bottom border |
| `vertical` | Both vertical borders |
| `none` | No border |

### 10.6. Table Colors

Table colors follow the same rules as bordered blocks:

- `color` changes table text color.
- If `border-color` is omitted, `color` also determines the border color.
- If `border-color` is specified, it overrides the border color independently.
- `title-color` changes the heading color independently.

### 10.7. Standard Table Compatibility

Standard Markdown tables remain supported.

The `@@table` wrapper is optional and is used when table-level attributes are needed.

## 11. Forms

Forms are used to send data to the server. They are enclosed between `@@` markers.

### 11.1. Form Syntax

```tmkup
@@ {action="/path" method="post"}
... fields ...
@@
```

Required form attributes:

| Attribute | Description |
|---|---|
| `action` | Destination path for submitted data |
| `method` | Submission method. Only `post` is supported. |

### 11.2. Form Appearance Attributes

Forms support the common block attributes defined in Section 2.3.

Example:

```tmkup
@@ {action="/submit" method="post" title="Contact Form" color="cyan" border-color="blue" border="rounded"}
[Your name] {type="text" name="username" placeholder="Name" required}
[Email] {type="email" name="email" placeholder="user@example.com" required}
[Submit] {type="submit"}
@@
```

Form appearance attributes control the presentation of the form. They do not replace or modify its submission attributes.

Color behavior follows the same rules as bordered blocks:

- `color` changes the form content color and, unless overridden, the border color.
- `border-color` changes only the border color.
- `title-color` changes the heading color independently.

### 11.3. Text Fields

Text fields use the `type` attribute.

```tmkup
[Your name] {type="text" name="username" placeholder="Name" required}
[Email] {type="email" name="email" placeholder="user@example.com" required}
[Password] {type="password" name="password" required}
[Message] {type="textarea" name="message" rows="4" placeholder="Text"}
```

| Attribute | Description |
|---|---|
| `type` | Field type |
| `name` | Submitted field name |
| `placeholder` | Optional placeholder text |
| `required` | Marks the field as required |
| `rows` | Textarea height in rows |

Supported text field types:

- `text`
- `email`
- `password`
- `textarea`

### 11.4. Checkboxes

Checkboxes use the `checkbox` type.

```tmkup
[I agree to the terms] {type="checkbox" name="agree" checked}
[Subscribe to newsletter] {type="checkbox" name="newsletter"}
```

The `checked` attribute marks a checkbox as selected by default.

### 11.5. Radio Buttons

Radio buttons use block syntax.

```tmkup
[radio name="gender"]
  [Male] {value="male" checked}
  [Female] {value="female"}
[/radio]
```

The `name` attribute identifies the radio group. Each option has its own `value`.

The `checked` attribute marks the initially selected option.

### 11.6. Select Dropdown

Select fields use block syntax.

```tmkup
[select name="city"]
  [Moscow] {value="msk" selected}
  [Saint Petersburg] {value="spb"}
  [Kazan] {value="kzn"}
[/select]
```

The `selected` attribute marks an initially selected option.

#### Multiple Selection

The `multiple` attribute allows selecting multiple options.

```tmkup
[select name="tags" multiple]
  [News] {value="news" selected}
  [Blog] {value="blog"}
  [Articles] {value="articles" selected}
[/select]
```

### 11.7. Buttons

Submit and reset buttons use the following syntax.

```tmkup
[Submit] {type="submit"}
[Reset] {type="reset"}
```

### 11.8. Hidden Fields

Hidden fields are defined using the `hidden` type.

```tmkup
[ ] {type="hidden" name="token" value="abc123"}
```

### 11.9. Full Form Example

```tmkup
@@ {action="/register" method="post" title="Registration" color="cyan" border-color="blue" border="rounded"}

[Your name] {type="text" name="username" placeholder="Name" required}
[Email] {type="email" name="email" placeholder="user@example.com" required}
[Password] {type="password" name="password" required}

Country:
[select name="country"]
  [Russia] {value="ru" selected}
  [USA] {value="us"}
  [Germany] {value="de"}
[/select]

[I agree to the terms] {type="checkbox" name="agree" required}
[Subscribe to newsletter] {type="checkbox" name="newsletter" checked}

Gender:
[radio name="gender"]
  [Male] {value="male" checked}
  [Female] {value="female"}
[/radio]

[Comment] {type="textarea" name="message" rows="4"}

[Submit] {type="submit"}
[Reset] {type="reset"}

@@
```

## 12. Footnotes

Footnotes use numbered identifiers.

```tmkup
Text with a footnote[^1] and another one[^2].

[^1]: First footnote
[^2]: Second footnote with *formatting*
```

A reference uses `[^number]`. Its corresponding definition begins with the same identifier followed by a colon.

## 13. Comments

Comments are ignored during document display.

### 13.1. Single-Line Comments

```tmkup
// Single-line comment
```

### 13.2. Multi-Line Comments

```tmkup
/*
   Multi-line
   comment
*/
```

## 14. Variables

Variables are defined in the metadata block and referenced using double curly braces.

### 14.1. Variable Definition

```tmkup
---tmk-meta
variables:
  site_name: "TNet Hub"
  date: "2024-06-10"
---tmk-meta
```

### 14.2. Variable Usage

```tmkup
Welcome to {{ site_name }}.
Today: {{ date }}.
```

The variable name inside `{{ }}` identifies the value defined in the metadata block.
